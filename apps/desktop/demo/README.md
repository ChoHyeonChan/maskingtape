# 데모 파일 세트 — 제출 영상·스크린샷용

데스크톱 앱의 드래그&드롭 배치 처리를 시연할 때 쓰는 **합성(가짜) 문서 5종**이다.
실제 개인정보는 한 건도 없다 — 이름·번호·주소 전부 지어낸 값이고,
주민등록번호·사업자등록번호·카드번호는 **탐지가 실제로 걸리도록 체크섬만 유효하게** 만들었다.

시연 중에 생기는 `*_masked.*` 결과물은 [.gitignore](../.gitignore)에서 걸러지므로 커밋되지 않는다.

## 파일 구성

| 파일 | 형식 | 노리는 것 |
|---|---|---|
| `01_상담기록.txt` | txt | 가장 흔한 형태 — 이름·전화·이메일·주민번호·주소가 문장 속에 섞여 있다 |
| `02_거래처명단.csv` | csv | 표 형태 — 사업자등록번호·계좌번호가 열로 반복된다 |
| `03_출장신청서.md` | md | 문서 형태 — 여권번호 2건, 마크다운 표 안의 값도 처리되는지 |
| `04_가입신청.json` | json | 구조화 데이터 — 키/값 안의 개인정보 |
| `05_공지사항.txt` | txt | **개인정보가 없는 문서** — 탐지 0건이 정상 (오탐이 없다는 걸 보여준다) |

한 번에 5개를 전부 드롭하면 **파일 5개 / 탐지 33건**이 나온다. 규칙 전용 모드 기준이며,
core `Pipeline.scan()`으로 실측한 값이다:

| 파일 | 탐지 | 내역 |
|---|---|---|
| 01_상담기록.txt | 6건 | 주소 1 · 이메일 1 · 이름 1 · 전화번호 2 · 주민번호 1 |
| 02_거래처명단.csv | 12건 | 계좌번호 4 · 사업자등록번호 4 · 전화번호 4 |
| 03_출장신청서.md | 7건 | 주소 1 · 카드번호 1 · 이메일 1 · 이름 1 · 여권번호 2 · 전화번호 1 |
| 04_가입신청.json | 8건 | 계좌번호 1 · 주소 1 · 카드번호 1 · 이메일 2 · 전화번호 2 · 주민번호 1 |
| 05_공지사항.txt | 0건 | — |

코어가 현재 지원하는 **9종(주민번호·전화번호·이메일·이름·주소·카드번호·사업자등록번호·여권번호·계좌번호)이 전부 한 번씩 나온다.**

## 시연 시나리오

1. **빈 화면** — 앱을 실행하면 점선 드롭존만 있는 상태
2. **드롭** — 이 폴더의 파일 5개를 한꺼번에 끌어다 놓는다 → 목록에 5줄, 전부 "대기"
3. **전략 선택** — 툴바에서 `가리기(***)` / `라벨([전화번호])` / `가명(홍길동→가명)` 중 하나
4. **시작** — `비식별화 시작` → 진행률 막대가 차오르고 상태가 대기 → 처리 중 → 완료로 바뀐다
5. **결과 확인** — 완료된 줄을 클릭하면 **원문(하이라이트) vs 마스킹 결과** 비교 다이얼로그
6. **저장 확인** — 폴더 열기 아이콘 → 원본 옆에 `_masked` 파일이 생긴 걸 보여준다

### 곁들이면 좋은 장면

- **오탐 없음**: `05_공지사항.txt`가 "탐지 없음"으로 끝나는 줄. 개인정보 도구에서 오탐은 신뢰 문제라 짚을 가치가 있다.
- **전략 비교**: 같은 파일을 `가리기`와 `라벨`로 각각 돌려 결과를 나란히 보여주면 차이가 한눈에 들어온다.
- **취소**: 처리 중 `취소`를 누르면 남은 파일이 "대기"로 남는다 — 중단해도 망가지지 않는다는 점.
- **이름 정밀 탐지(LLM)**: 아래 참고.

## 이름 탐지 — 규칙 모드의 한계를 그대로 보여주는 게 낫다

이 5개 파일에는 사람 이름이 **10개** 들어 있는데, **규칙 전용 모드는 그중 2개**(`김민서`, `윤하늘`)만 잡는다.
나머지는 표의 "담당자" 칸처럼 문맥 단서가 없는 자리에 있어서다.

이건 버그가 아니라 한국어 이름 탐지의 본질적 어려움이고, **우리가 로컬 LLM 하이브리드를 쓰는 이유 그 자체**다.
시연에서는 이 순서를 권한다:

1. 규칙 모드로 먼저 돌려서 이름이 2건만 잡히는 걸 보여준다
2. **이름 정밀 탐지**를 켜고 같은 파일을 다시 돌린다
3. 잡히는 이름이 늘어나는 걸 보여준다

> 켜려면 이 PC에 Ollama가 실행 중이고 모델(`ollama pull qwen2.5:7b`)이 있어야 한다.
> 준비가 안 됐으면 해당 파일만 실패로 표시되고 코어가 준 안내 문구가 그대로 보인다.
> **영상 촬영 전에 반드시 미리 한 번 돌려볼 것** — 현장에서 처음 켜면 모델 다운로드로 시간이 간다.

## 스크린샷 체크리스트

제출 자료에 쓸 화면. 시나리오 순서대로 찍으면 그대로 나온다.

- [ ] 빈 드롭존 (앱 첫인상)
- [ ] 파일 5개가 목록에 올라온 상태 (전부 "대기")
- [ ] 처리 중 — 진행률 막대 + 상태 칩이 섞여 있는 순간
- [ ] 완료 — 5줄 전부 완료, 각 줄에 탐지 요약이 보이는 상태
- [ ] 결과 비교 다이얼로그 (원문 하이라이트 ↔ 마스킹 결과)
- [ ] `05_공지사항.txt`의 "탐지 없음" 줄
- [ ] (선택) 이름 정밀 탐지 켠 전/후 비교
- [ ] (선택) 탐색기에 `_masked` 파일이 생긴 화면

## 주의

- **처리 결과를 이 폴더에 그대로 두고 다시 드롭하지 말 것.** `_masked` 파일은 재처리가 거부되도록 막혀 있지만, 화면이 지저분해진다. 촬영 전에 `*_masked.*`를 지우고 시작하는 게 깔끔하다.
- 처리에는 `maskingtape` CLI가 PATH에 있거나 `apps/api` 서버가 떠 있어야 한다. 자세한 건 [../README.md](../README.md)의 백엔드 절 참고.
