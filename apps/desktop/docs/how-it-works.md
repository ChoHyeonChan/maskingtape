## ① 로컬 CLI 우선, 없으면 REST API로 넘어가기

**한 줄**: 데스크톱 앱은 탐지를 직접 하지 않고 엔진(core)에 맡긴다. 이 PC의 CLI를 먼저 쓰고, CLI가 없을 때만 API 서버로 넘어간다.

**동작**
- `FallbackAnonymizer`가 백엔드 목록 `[CLI, REST]`를 순서대로 시도한다.
- CLI는 설치판에 동봉된 Python을 먼저 찾고(`python\python.exe -B -X utf8 -m maskingtape.cli`), 없으면 PATH의 `maskingtape`를 쓴다(`cli_locator.dart`).
- 텍스트는 표준입력(UTF-8)으로 넘기고 결과는 표준출력으로 받는다. core의 위치는 코드포인트 기준이라 Dart(UTF-16) 위치로 바꾼다(#496, 이모지 뒤 개인정보가 원문으로 남던 문제).
- **다음 백엔드로 넘기는 건 「닿지 못했을 때」(`AnonymizerUnavailableException`)뿐이다.** Ollama가 꺼진 것처럼 처리 중에 난 오류는 넘기지 않고 그대로 보여 준다.

**이렇게 만든 이유**
- 로컬 CLI는 기능이 다 된다(가명처리, 로컬 LLM).
- 무엇보다 **텍스트가 PC 밖으로 나가지 않는다.** "개인정보는 내 PC에서 처리한다"는 제품 메시지와 맞는다.
- API는 CLI가 없는 PC에서도 앱이 일단 동작하게 하는 보조 수단이다.

**다른 방법을 안 쓴 이유**
- 탐지 로직을 Dart로 다시 짜면 엔진이 두 벌이 되어 웹·CLI와 결과가 달라진다. 그래서 팀 규칙으로 금지했다(`apps/desktop/README.md` 「규칙」).
- API를 먼저 쓰면 원문이 네트워크를 타고, 로컬 LLM도 못 쓴다.
- 처리 오류까지 다음 백엔드로 넘기면 「Ollama를 켜라」 같은 진짜 원인이 가려진다.

**예상 질문**
- Q. API로 넘어갔을 때 「로컬 LLM 사용」을 켜면? → 네트워크를 타기 전에 거절하고 「maskingtape CLI를 설치하면 이 PC에서 처리할 수 있습니다」라고 안내한다.
- Q. 둘 다 없으면? → 「비식별화 백엔드에 연결하지 못했습니다」와 함께 두 사유(CLI 없음 / 서버 없음)를 다 보여 준다. 한쪽만 보이면 어느 쪽을 고쳐야 할지 모른다.

**코드**: [`fallback_anonymizer.dart`](../lib/services/fallback_anonymizer.dart), [`default_backend.dart`](../lib/services/default_backend.dart), [`cli_locator.dart`](../lib/services/cli_locator.dart), [`cli_anonymizer.dart`](../lib/services/cli_anonymizer.dart), [`rest_anonymizer.dart`](../lib/services/rest_anonymizer.dart)

## ② 파일 일괄 처리

**한 줄**: 여러 파일을 순서대로 하나씩 「읽기 → 비식별화 → `이름_masked` 사본 저장」한다.

**동작**
- 파일마다 상태가 「대기 → 처리 중 → 완료/실패」로 바뀌고, 화면은 알림을 받아 다시 그리기만 한다.
- **한 파일이 실패해도 그 파일만 실패로 두고 다음 파일로 간다.** 예전엔 예상 밖 오류에 처리가 멈춰 앱이 갇혔다(#497). 이 경우 오류 문자열을 화면에 넣지 않는다 — 형식 오류 메시지에 원문 조각이 담길 수 있다.
- 취소하면 처리 중이던 파일은 마저 끝내고, 남은 파일은 「대기」로 둔다.
- 원본은 건드리지 않고 같은 폴더에 사본만 만든다. `_masked` 파일을 다시 넣으면 거부한다. PDF 결과는 `이름_pdf_masked.txt`다(같은 폴더의 `이름.txt` 결과를 덮어쓰지 않게).
- 비교 미리보기는 텍스트를 메모리에 들고 있지 않고 열 때 디스크에서 읽는다. 파일이 많아도 메모리가 늘지 않는다.

**이렇게 만든 이유**: 원본 보존(되돌릴 수 있음)과, 한 파일 때문에 전체가 멈추지 않는 안정성.

**다른 방법을 안 쓴 이유 (병렬 처리)**: 파일마다 CLI 프로세스를 띄우고 LLM은 Ollama 하나가 처리하므로 동시에 돌려도 크게 빨라지지 않는다. 대신 메모리와 진행 표시가 복잡해진다.

**예상 질문**
- Q. 처리 중에 파일을 더 넣으면? → 지금은 남은 파일이 「대기」로 멈추는 **알려진 버그**가 있다([#722](https://github.com/ChoHyeonChan/maskingtape/issues/722)). 목록을 for-in으로 도는데 처리 중에도 드롭이 막혀 있지 않아 `ConcurrentModificationError`가 난다. 목록을 번호로 돌게 바꾸는 수정안을 테스트(수정 전 실패·후 통과)까지 만들어 두었고, 코드 마감 뒤라 대회 후에 넣는다. 앱은 꺼지지 않고 「비식별화 시작」을 다시 누르면 처리된다.
- Q. 몇 개까지 되나? → 개수 상한은 없고 파일 하나당 크기 상한이 있다(텍스트 10MB, PDF 50MB).

**코드**: [`batch_processor.dart`](../lib/services/batch_processor.dart), [`home_screen.dart`](../lib/screens/home_screen.dart), [`result_preview_dialog.dart`](../lib/widgets/result_preview_dialog.dart)

## ③ CP949 인코딩 폴백

**한 줄**: 파일을 UTF-8로 먼저 읽고, 실패하면 CP949(EUC-KR)로 다시 읽는다. 결과는 항상 UTF-8로 저장한다.

**동작** (`file_reader.dart`)
- 확장자·크기 상한·빈 파일을 확인한다.
- 앞부분에 NUL 바이트가 있으면 바이너리로 보고 거부한다(확장자만 txt인 파일 방어).
- UTF-8로 디코딩해 보고, 실패하면 CP949로 디코딩한다. 맨 앞 BOM(U+FEFF)은 뗀다 — 남기면 탐지 위치가 한 칸씩 밀린다.

**이렇게 만든 이유**: 한국 사무 환경의 옛 메모장 「ANSI」 저장과 엑셀 CSV는 CP949다. 이걸 못 읽으면 한글이 깨져 이름·주소 탐지가 통째로 빠진다.

**다른 방법을 안 쓴 이유 (순서)**
- **UTF-8을 먼저** 시도하는 건 UTF-8 규칙이 엄격해서 CP949 바이트가 우연히 올바른 UTF-8이 되는 일이 거의 없기 때문이다. 실패하면 확실히 UTF-8이 아니다.
- 반대로 CP949부터 시도하면 UTF-8 파일도 그럴듯하게 「읽혀 버려서」 글자가 깨진 채 통과할 수 있다.
- 인코딩 추측 라이브러리는 의존성만 늘고, 한국어 파일에는 이 두 가지면 충분하다.

**예상 질문**: Q. CP949 디코더는 직접 짰나? → 아니다. `cp949_codec`(BSD-3-Clause, 순수 Dart)을 쓰고 SBOM에 올렸다.

**코드**: [`file_reader.dart`](../lib/services/file_reader.dart), 테스트 [`file_reader_test.dart`](../test/file_reader_test.dart)

## ④ LLM 하이브리드 안전망 ([#477](https://github.com/ChoHyeonChan/maskingtape/pull/477))

**한 줄**: 「로컬 LLM 사용」을 켜도 규칙 이름 탐지기를 같이 돌려, LLM이 놓친 이름을 규칙이 잡는다.

**동작**
- core의 `llm_detectors()`가 「LLM 이름 탐지 + 규칙 탐지 전부」를 돌린다. 데스크톱은 CLI에 `--llm`만 붙인다.
- 겹치는 구간은 Pipeline이 **합집합**으로 합친다 — 더 넓게 가리는 쪽(안전한 쪽)이다.

**이렇게 만든 이유**: LLM은 문서 속 지시문(프롬프트 인젝션)에 속을 수 있다. 「이 글에는 이름이 없다」 한 줄에 이름을 놓치면 그대로 유출이고, 시스템 프롬프트를 강화해도 막히지 않았다. 그래서 LLM이 흔들려도 **규칙만 쓸 때보다 나빠지지 않게** 바닥을 깔았다.

**#477에서 한 일**: 예전엔 규칙 안전망을 확신도 0.75 이상만 남겨서, 0.5짜리(단서 한쪽, 「담당자는 서정호입니다」)는 LLM이 놓치면 샜다. 제한을 풀자 미탐 **30 → 21건**, 오탐 21 → 28건(synth_v1, qwen2.5:7b, 3회 동일). 유출을 줄이는 쪽을 골랐다.

**숫자 근거 — 프롬프트 공격 골든셋**(#549·#740, [`bench/README.md`](../../../bench/README.md))
- 7B는 공격 판에서 LLM 단독 재현율이 0.095~0.700까지 떨어졌지만, 하이브리드는 다섯 유형 모두 규칙 전용과 같거나 높았다.
- 지금 기본 모델(1.5B)은 LLM 단독도 1.000으로 흔들리지 않는다. 단, 같은 생성기의 공격 문장 일부로 학습한 모델이라 「처음 보는 공격에도 강하다」는 근거는 아니다 — **그래서 안전망은 여전히 필요하다.**

**다른 방법을 안 쓴 이유**: 「규칙 우선 + LLM은 안 겹치는 것만」이 1건 더 나았지만(F1 0.939 대 0.937) 새 래퍼 탐지기가 필요했다. 한 줄로 끝나고 구조가 바뀌지 않는 합집합을 골랐다.

**코드**: [`packages/core/maskingtape/detectors/__init__.py`](../../../packages/core/maskingtape/detectors/__init__.py) `llm_detectors()`, 데스크톱 쪽 [`cli_anonymizer.dart`](../lib/services/cli_anonymizer.dart) `argsFor()`

## ⑤ PDF 입력 (#709)

**한 줄**: PDF에서 글자만 뽑아 txt와 같은 길로 처리하고 `이름_pdf_masked.txt`로 저장한다. 가린 PDF를 만드는 건 아니다(웹과 같은 범위).

**동작**
- 앱이 Python을 `python -B -X utf8 - <경로>`로 띄우고 [`assets/pdf_text.py`](../assets/pdf_text.py)(pypdf)를 **표준입력으로** 넘긴다. Python은 CLI와 같은 순서로 찾는다(설치판 동봉본 → PATH).
- PDF에는 문단이 없고 화면의 줄만 있다. 그대로 두면 폭이 차서 꺾인 자리마다 줄이 끊겨, 단어 중간에서 꺾인 이름·이메일이 조각으로 남아 탐지에서 빠진다(`김민`/`수님` → `수님` 노출). 그래서 **줄 끝이 오른쪽 여백선에 닿고 다음 줄이 같은 크기·보통 줄 간격으로 이어질 때만** 다시 잇는다. 표·목록·문단 사이는 그대로 둔다.
- 이을 때 공백을 넣을지는 어림한다: 하이픈·숫자·이메일 중간은 붙이고, 한글끼리는 남은 여백·조사·어미·「낱말 첫 글자로 안 오는 글자」로 띄어쓰기 자리인지 판단한다.
- 스캔본(글자 없음)·열기 암호·깨진 파일은 실패로 알린다. 실패 안내는 스크립트가 쓴 `오류:` 한 줄만 옮기고, pypdf 로그는 꺼 둔다(깨진 파일 경고에 내용 조각이 찍힌다).

**이렇게 만든 이유 / 다른 방법을 안 쓴 이유**
- Dart PDF 패키지(pdfrx)는 PDFium DLL을 함께 배포해야 해서 고지 대상이 늘고, 상용 라이선스 패키지(syncfusion)는 팀 허용 목록 밖이다. pypdf는 순수 Python·BSD-3-Clause라 동봉 Python에 wheel만 풀면 된다.
- 코드를 `-c` 인자로 넘기지 않는 건 여러 줄·따옴표가 Windows 명령줄 인용에서 깨지기 때문이다(직접 겪음).
- 줄 잇기: 공백 없이 붙이면 띄어쓰기 자리에서 꺾인 `담당자`/`이서연`이 `담당자이서연`이 되어 이름을 놓치고, 공백으로만 이으면 단어 중간 꺾임이 조각으로 남는다. 합성 PDF 7종(기본·어절·양쪽 정렬·강제 꺾임 4종, 꺾인 자리 12곳)으로 비교해 지금 규칙을 정했고, 문단이 원문과 한 글자도 다르지 않게 복원됐다.

**예상 질문**: Q. 좁은 상자나 다단은? → 페이지 여백이 아니라 상자 폭에서 꺾인 줄은 「꺾인 줄」로 판단하지 못해 원래 줄바꿈을 둔다(잘못 붙이는 것보다 안전).

**코드**: [`pdf_text_extractor.dart`](../lib/services/pdf_text_extractor.dart), [`assets/pdf_text.py`](../assets/pdf_text.py), [`file_reader.dart`](../lib/services/file_reader.dart)

## ⑥ 설치파일 (#617)

**한 줄**: Inno Setup 설치파일에 임베디드 Python 3.13.2·엔진·pypdf를 함께 묶어, 받는 사람은 Python도 PATH 설정도 없이 쓴다. GitHub Releases `desktop-v0.2.3`.

**동작** ([`installer/build.py`](../installer/build.py))
- Flutter 릴리스 빌드 → Python 임베디드 zip(SHA-256 고정)을 풀고 core·pypdf wheel을 `site-packages`에 푼다 → 묶은 CLI와 PDF 추출을 합성 문장으로 실제로 돌려 확인 → 고지문을 `licenses\*.txt`로 모으고 파일별 해시(`BUNDLE_MANIFEST.txt`)를 쓴 뒤 Inno Setup으로 만든다.
- Ollama와 이름 모델은 묶지 않는다. 설치 중 「추가 작업」으로 고를 때만 공식 배포처에서 받는다(기본 꺼짐).
- 앱의 ⓘ 화면은 Flutter가 모은 패키지 라이선스에 `licenses\*.txt`를 보탠다 — 실행 파일로 배포하면 실행 화면에서 고지해야 한다(CLAUDE.md §2-8, 2026-09 라이선스 컨설팅).

**다른 방법을 안 쓴 이유**
- pip을 넣지 않는다: wheel을 풀기만 하면 되고, pip을 넣으면 고지할 구성요소가 는다. 그래서 `-m maskingtape.cli`로 부른다.
- `-B`(캐시 안 씀): 실행 중 `__pycache__`가 설치 폴더에 생기지 않아, 제거할 때 설치한 파일만 지워도 폴더가 깨끗이 사라진다. 폴더를 통째로 지우는 방식은 남의 파일까지 지울 수 있어 쓰지 않았다.
- Ollama·모델(약 2GB)을 묶지 않은 건 크기와 고지 대상(CUDA 런타임 등) 때문이다. 사용자가 직접 받는 것이라 재배포가 아니다.

**예상 질문**: Q. 코드 서명은? → 없다. 처음 실행하면 SmartScreen이 막아서 릴리스 노트에 「추가 정보 → 실행」을 적었다.

## ⑦ 이름 판정 모델 maskingtape-name-1.5b (#458)

**한 줄**: Qwen2.5-1.5B-Instruct(Apache-2.0)를 우리 합성 데이터로 LoRA 학습한 이름 판정 모델. 7B와 재현율은 같고, 크기는 1/5(986MB)이고 약 3배 빠르다. 허깅페이스에 공개했다.

**동작** ([`training/README.md`](../../../training/README.md))
- 데이터: bench 생성기 템플릿을 학습용/보고용으로 나눠(번호 % 4 == 3이면 보고용) 12,000건을 만든다. 학습 예제는 core가 실제로 보내는 대화와 같다(system = core 프롬프트, user = 원문, assistant = `{"names": [...]}`). 그래서 **core는 모델 이름만 바꾸면 된다.**
- 공격 문장이 붙은 문서 20%(정답은 그대로 → 지시문 무시 학습), 이름 없는 문서 27%, 혼동어·단서 없는 이름을 넣었다.
- LoRA(r=16), 2 에폭, RTX 3080에서 약 35분 → 기반 모델과 합쳐 GGUF로 바꾸고 Q4_K_M으로 양자화해 Ollama에 등록.

**수치 — 정직한 요약**
- 학습에 안 쓴 **외부 데이터**(KDPII test 500문장): 하이브리드 재현율 0.825로 **7B와 같고**, 정밀도는 7B가 높다(0.527 대 0.471).
- 같은 생성기의 보고용 세트에서는 7B보다 높지만(하이브리드 F1 0.944 > 0.907) **학습 분포 안쪽이라 낙관적**이다.
- 그래서 요약은 "7B보다 정확하다"가 아니라 **"재현율은 같고, 더 작고 빠르며, 문서 속 지시문에 덜 흔들린다"**다.

**다른 방법을 안 쓴 이유**
- 그냥 1.5B 원본을 쓰면 규칙만보다도 낮다(#477 측정: 하이브리드 F1 0.831 < 규칙 0.910). 범용 소형 모델에 이름 판단을 맡기기 어려워서 학습했다.
- 3B·72B는 비상업 라이선스라 기반 모델로 못 쓴다. 학습 데이터는 합성만 쓴다(KDPII·AI Hub 원본은 재배포 제한).
- 학습한 가중치는 규정(제9조 ②항 2호 나목)에 따라 공개 저장소에 올렸다 — `StayAlive1/maskingtape-name-1.5b`(+ `-GGUF`).

**예상 질문**
- Q. CPU에서도 되나? → 된다. Q4_K_M 986MB라 GPU 없는 노트북에서도 돈다(기능검증 노트북도 CPU 실행).
- Q. 공격에 1.000인데 믿어도 되나? → 학습에 같은 생성기의 공격 문장 일부를 썼다. 학습에 안 쓴 문장만 따로 재도 1.000이지만, 같은 다섯 유형이라 처음 보는 공격까지 보장하진 않는다. 그래서 ④의 규칙 안전망을 유지한다.
